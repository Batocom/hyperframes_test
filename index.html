While building the POS system

I ended up writing down roughly

40

SMALL RULES

like the ones in RULES.md

They're not random, they all serve one of four goals

things stay predictable... the code stays modular...

the system can scale... and everything stays consistent

PREDICTABLE
MODULAR
SCALABLE
CONSISTENT

I'm not going to read you all forty

the whole point of writing them down

so nobody has to memorize them

But here's one example from each group

GOAL 1

PREDICTABLE

every function hands back its answer

in the exact same shape, every time

like every order coming out on the same size plate

no matter what you ordered

GOAL 2

MODULAR

the database code, the business logic, and the screens

never touch each other directly

they only talk through one designated doorway

GOAL 3

SCALABLE

every change to the database gets logged automatically

so if something breaks six months from now

you can see exactly what happened and when

GOAL 4

CONSISTENT

every file starts with the same short header block

so opening any file feels familiar

of like starting from zero

That's four ideas echoed about ten times each

across different corners of the project

SAME PATTERN

applied everywhere it's needed

Once the idea clicks

the other thirty-six are just the same four thoughts wearing different outfits

something you'll run twice and forget — skip all of this

things you'll keep extending, maintaining, and handing off
